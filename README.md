# Tourney Hub 🎲

เครื่องมือจัดทัวร์นาเมนต์ครบวงจร ใช้ได้กับทุกเกม — สุ่มแบ่งทีม หมุนวงล้อ จัดสายแข่ง กรอกผล คำนวณเงินรางวัล
และเก็บประวัติผู้เล่น ทำงานในเบราว์เซอร์ล้วน ไม่มีเซิร์ฟเวอร์ deploy เป็น static site บน GitHub Pages

**เว็บจริง:** [phawit-s.github.io/rov-tournament](https://phawit-s.github.io/rov-tournament/)

## สิทธิ์

| บทบาท | ได้อะไร | ใครให้ |
| --- | --- | --- |
| **ผู้ใช้ทั่วไป** | หน้าบ้านทั้งหมด สมัครแข่ง โดเนท ขอเพลง | แค่ล็อกอิน |
| **สตรีมเมอร์** | + เปิดสตูดิโอ จัดการ **ช่องของตัวเอง** และทัวร์ของตัวเอง | ผู้ดูแลอนุมัติคำขอ (เอกสาร `streamers/{uid}`) |
| **ผู้ดูแลระบบ** 👑 | + เห็นผู้ใช้ทั้งระบบ แก้ช่องคนอื่น ให้/ถอดสิทธิ์ | อีเมลใน `ownerEmails()` หรือเอกสาร `admins/{uid}` |

**การขอเป็นสตรีมเมอร์:** ล็อกอิน → เปิด `/studio/` → กรอกชื่อช่อง/แพลตฟอร์ม/ลิงก์ →
ใบไปโผล่ที่ `/studio/roles/` ให้ผู้ดูแลกด **อนุมัติ** แล้วสิทธิ์มีผลทันทีไม่ต้องรีเฟรช
ใบที่ถูกปฏิเสธยื่นใหม่ได้ไม่จำกัดครั้ง

กติกาฝั่งเซิร์ฟเวอร์บังคับไว้แล้วว่าคนขอตั้งสถานะได้แค่ `pending` — อนุมัติตัวเองไม่ได้
และ **เปิดช่องใหม่ได้เฉพาะคนที่มีสิทธิ์สตรีมเมอร์** (ช่องที่มีอยู่ก่อนหน้ายังแก้ได้ตามปกติ)

นอกจากนี้ยังมี **รหัสผู้จัดสำหรับเครื่องนี้** เป็นทางเข้าสำรอง — ปลดได้เฉพาะเครื่องมือที่
ทำงานในเบราว์เซอร์ล้วน (สุ่มทีม วงล้อ widget ประวัติ) ข้อมูลบนคลาวด์ยังถูกปฏิเสธเหมือนเดิม

### ตั้งผู้ดูแลคนแรก — ทำครั้งเดียว

มีขั้นตอนเดียวคือ **publish `firestore.rules`**

1. เปิด [`firestore.rules`](firestore.rules) หาบรรทัด `ownerEmails()`
   แล้วแก้เป็นอีเมล Google ที่คุณใช้ล็อกอินเว็บนี้ (ใส่หลายอีเมลได้)
2. ส่งกติกาขึ้นไป — เลือกทางไหนก็ได้

   ```bash
   npx firebase-tools deploy --only firestore:rules --project rov-tournament
   ```

   หรือ Firebase Console → Firestore Database → Rules → วางทั้งไฟล์ → **Publish**
3. ล็อกอินเข้าเว็บด้วยอีเมลนั้น เมนูหลังบ้านจะขึ้นเองทันที

> กติกาไม่ได้ขึ้นตามตอน deploy เว็บ ต้องสั่งแยกทุกครั้งที่แก้ `firestore.rules`
> ([`firebase.json`](firebase.json) มีไว้ให้คำสั่งด้านบนรู้ว่าจะส่งไฟล์ไหน)

ไม่ต้องสร้างเอกสารอะไรด้วยมือ เพราะอีเมลในกติกาถือเป็นผู้ดูแลอยู่แล้ว

> ⚠️ **สิทธิ์สตรีมเมอร์ต้องใช้กติการุ่นใหม่**
> `streamers/` กับ `streamerRequests/` เพิ่งถูกเพิ่มเข้ามาใน `firestore.rules`
> ถ้ายังไม่ publish รุ่นล่าสุด ปุ่ม "ส่งคำขอ" จะขึ้น `permission-denied`
> และไม่มีใครเป็นสตรีมเมอร์ได้เลย (ผู้ดูแลเดิมยังใช้ได้ตามปกติ)

### เพิ่มผู้ดูแลคนอื่น / ให้สิทธิ์สตรีมเมอร์

ทำจากหน้าเว็บได้เลยที่ **สตูดิโอ → สิทธิ์และคำขอ** (`/studio/roles/`)

1. ให้เขาล็อกอินเข้าเว็บก่อนหนึ่งครั้ง ชื่อจะไปโผล่ในรายชื่อผู้ใช้เอง
2. เลือกชื่อจากรายการแล้วกด **ให้สิทธิ์** (สตรีมเมอร์) หรือ **เพิ่ม** (ผู้ดูแล)
3. สิทธิ์มีผลทันทีไม่ต้องรีเฟรช — ถอดคืนได้ที่รายการเดียวกัน

ถ้าเขาส่งคำขอเข้ามาเองอยู่แล้ว กด **อนุมัติ** ที่ใบคำขอได้เลย ไม่ต้องเลือกจากรายชื่อซ้ำ

### รหัสสำหรับเครื่องนี้

รหัสตั้งต้นคือ `TH-2026-ADMIN` เปลี่ยนได้สองทาง

1. แก้ `FALLBACK_HASH` ใน [`lib/gate.ts`](lib/gate.ts)
2. หรือใส่ตัวแปร `NEXT_PUBLIC_ADMIN_PIN_HASH` ตอน build

ค่าที่ใส่ต้องเป็น SHA-256 ของรหัส หาได้ด้วย

```bash
node -e "console.log(require('crypto').createHash('sha256').update('รหัสใหม่').digest('hex'))"
```

> ⚠️ **สิ่งที่ล็อกได้จริงคือข้อมูล ไม่ใช่หน้าจอ**
> เว็บเป็นไฟล์ static ใครเปิด devtools เป็นก็บังคับให้เมนูโผล่ได้เสมอ
> ไม่ว่าจะล็อกยังไง แต่ทุกคำสั่งที่แตะข้อมูลบนคลาวด์จะถูก `firestore.rules`
> ปฏิเสธอยู่ดี เพราะกติกานั้นรันบนเครื่อง Google ไม่ใช่ในเบราว์เซอร์
> — อ่านเอกสารสิทธิ์ของคนอื่นไม่ได้ และสร้างเอกสารสิทธิ์ให้ตัวเองไม่ได้

## Widget สำหรับสตรีม

ทุกตัวเป็นหน้าเว็บพื้นหลังโปร่งใส เอาไปวางเป็น **Browser Source** ได้ทั้ง OBS และ Streamlabs

| Widget | ขนาดแนะนำ | ทำอะไร |
| --- | --- | --- |
| `/widget/scoreboard` | 700 × 190 | สกอร์บั๊ก ชื่อสองทีม + สกอร์ + BO |
| `/widget/upnext` | 520 × 320 | คิวแมตช์ถัดไปพร้อมเวลา |
| `/widget/timer` | 420 × 220 | นับถอยหลังถึงแมตช์ หรือ `?mins=5` ทำตัวจับเวลาพักเบรก |
| `/widget/champion` | 700 × 400 | ป้ายแชมป์ตอนจบรายการ |
| `/widget/alert` | 700 × 300 | เด้งแจ้งเตือนตอนอนุมัติสลิปโดเนท/สมาชิก มีเสียง |

พารามิเตอร์ที่ใช้ได้: `?accent=ddaf64` (สีเน้น) · `?scale=1.3` (ขนาด) · `?solid=1` (พื้นทึบไว้ดูตัวอย่าง) ·
`#c=<id>` ดึงสดจากคลาวด์ (ใช้กับ OBS) · `#t=<id>` อ่านจาก localStorage เครื่องนี้ (ใช้พรีวิวเท่านั้น)

> OBS มีที่เก็บข้อมูลแยกจากเบราว์เซอร์ปกติ — widget ที่ใช้ `#t=` จะไม่เห็นข้อมูล
> ถ้าจะใช้จริงต้องเชื่อม Firebase แล้วใช้ `#c=`

## ระบบโดเนทและสมาชิก

- ผู้จัดใส่เลขพร้อมเพย์ → หน้าสนับสนุน `/c/#h=ชื่อช่อง` สร้าง **QR พร้อมเพย์พร้อมยอด** ให้อัตโนมัติ (คำนวณ EMVCo + CRC ในเครื่อง)
  ลิงก์นี้ก๊อปได้จากหน้า **ช่อง** ไม่ต้องพิมพ์เอง
- ผู้โอนกรอกชื่อ/ข้อความ แนบสลิป (ระบบย่อรูปให้เอง) แล้วกดส่ง
- ผู้จัดเห็นสลิปในแท็บ **โดเนท / สมาชิก** กดอนุมัติ → widget แจ้งเตือนเด้งขึ้นสตรีมทันที
- สมาชิกรายเดือน: ตั้งแพ็กเกจ (ชื่อ/ราคา/สิทธิพิเศษ) ผู้สมัครเลือกจำนวนเดือน อนุมัติแล้วระบบคิดวันหมดอายุให้

### กันสลิปปลอม/สลิปซ้ำ

ทำงานเป็นสามชั้น ชั้นแรกได้ฟรีตั้งแต่ยังไม่ตั้งอะไรเพิ่ม

1. **กันสลิปซ้ำ** — เว็บอ่าน QR บนสลิปแล้วทำ SHA-256 เป็นลายนิ้วมือ จดไว้ที่ `slipRefs`
   ซึ่งกติกาปิดการเขียนทับ สลิปใบหนึ่งจึงส่งได้ครั้งเดียวตลอดกาล ไม่ต้องมีเซิร์ฟเวอร์
2. **ยืนยันกับธนาคาร** — ตั้ง [Worker ตรวจสลิป](worker/README.md) แล้วใส่ URL ที่หน้า **ช่อง**
   ระบบจะเช็คว่าเงินเข้าจริง ยอดตรงกับใบ **และปลายทางเป็นเลขพร้อมเพย์ของช่องนั้นจริง**
   ผ่านครบสามข้อถึงจะติดป้าย `verified`
3. **อนุมัติเอง** — เปิดสวิตช์ไว้ ใบที่ `verified` จะขึ้นจอสตรีมทันทีโดยไม่ต้องรอผู้จัดกด

ไม่ตั้ง Worker ก็ใช้ได้ ใบจะค้างเป็น `unique` (อ่าน QR ได้ ไม่ซ้ำ) หรือ `none` (ไม่มี QR ต้องดูด้วยตา)
ให้ผู้จัดกดอนุมัติเองเหมือนเดิม

> ผลตรวจทุกฟิลด์เขียนได้จาก Worker ทางเดียว กติกา `firestore.rules` ปฏิเสธใบใหม่
> ที่พก `slipCheck: "verified"` มาเอง — ไม่งั้นแก้โค้ดหน้าเว็บก็อนุมัติตัวเองได้เลย

## เมนูสุ่มทีม

### การตั้งค่า

- ใส่ชื่อทีละคน (Enter) หรือวางทีเดียวหลายชื่อ (ขึ้นบรรทัดใหม่ / คั่นด้วย `,`) — กันชื่อซ้ำอัตโนมัติ
- คลิกที่ชื่อเพื่อแก้ไข กด ✕ เพื่อลบ
- เลือกได้ว่าจะ **กำหนดคนต่อทีม** (เช่น ทีมละ 5) หรือ **กำหนดจำนวนทีม**
- คนที่เหลือเศษเลือกได้ 3 แบบ: เก็บเป็น **ตัวสำรอง** / **ตั้งทีมใหม่** / **เกลี่ยลงทีมที่มีอยู่**
- ลำดับการเติม: **เต็มทีละทีม** (ตามที่ใช้กันปกติ) หรือ **วนทุกทีม**
- เปิดโหมดสุ่มเลนได้ — ดาบ / ป่า / กลาง / ท้าย / ซัพ
- แก้ชื่อทีมได้ (คลิกที่ชื่อทีมบนการ์ด)

### การจับสลาก

- กดทีละครั้ง = สุ่มทีละคน มีวงล้อชื่อหมุนแล้วหยุด → การ์ดชื่อเลื่อนเข้าช่องของทีมนั้น
- โหมดสุ่มอัตโนมัติ / ข้ามไปดูผลลัพธ์ทันที / ย้อนกลับทีละคน
- กด `Space` แทนการคลิกได้
- ออกผลแต่ละครั้งมีวงแหวนทองขยายออก จบครบทุกคนมีผงทองร่วง — ไม่ใช้พลุกระดาษ

### ผลลัพธ์

- คัดลอกเป็นข้อความไปวางในแชท
- คัดลอก **ลิงก์แชร์** — เปิดลิงก์แล้วเห็นผลชุดเดียวกันเป๊ะ (ฝังรายชื่อ + seed ไว้ใน URL)
- บันทึกเป็นรูป PNG
- สุ่มใหม่ด้วยรายชื่อเดิม หรือย้อนกลับไปแก้รายชื่อ

**ความยุติธรรม** — ผลลัพธ์คำนวณจาก `seed + รายชื่อ + การตั้งค่า` ด้วย PRNG แบบ deterministic
ใครก็ตรวจซ้ำได้ ใส่ seed เดิมกับรายชื่อเดิมต้องได้ผลเดิมเสมอ และ seed ถูกโชว์ไว้ตลอดเวลาจับสลาก
จะประกาศ seed ก่อนเริ่มก็ได้ เพื่อยืนยันว่าไม่ได้แอบสุ่มใหม่จนกว่าจะถูกใจ

**หน้าตา** — โทน luxury: ดำหมึก/งาช้าง + ทองแชมเปญ, พื้นผิวมีเกรน, เส้นคั่นบางๆ,
แสงนวลเคลื่อนช้าตามเมาส์, เสียงเอฟเฟกต์สังเคราะห์ (ปิดได้)
มีทั้ง **ธีมมืดและธีมสว่าง** สลับได้จากปุ่มมุมขวาบน (ครั้งแรกดูจากค่าระบบ แล้วจำไว้ให้)
รองรับมือถือเต็มรูปแบบ และเคารพ `prefers-reduced-motion`

## Deploy ขึ้น GitHub Pages

repo นี้มี workflow ให้แล้วที่ [.github/workflows/deploy.yml](.github/workflows/deploy.yml)

1. push ขึ้น branch `main`
2. ไปที่ **Settings → Pages → Build and deployment → Source** เลือก **GitHub Actions**
3. workflow จะ build แล้ว deploy ให้เอง ทุกครั้งที่ push

`basePath` ถูกตั้งอัตโนมัติจากชื่อ repo (`NEXT_PUBLIC_BASE_PATH=/<repo>`) ถ้า repo ชื่อ `<user>.github.io`

## ตั้งค่าหลังบ้าน (Firebase)

ไม่ตั้งก็ใช้ได้ แต่จะไม่มี: สมัครข้ามเครื่อง · ผลอัปเดตสดในสตรีม · โดเนท/สมาชิก · widget ใน OBS

1. สร้างโปรเจกต์ที่ [console.firebase.google.com](https://console.firebase.google.com)
2. **Authentication → Sign-in method** เปิด **Google** และ **Anonymous**
   (Anonymous ใช้กับหน้าโดเนท คนโอนไม่ต้องสมัครอะไร แต่ระบบได้ uid ไว้กันสแปม)
3. **Firestore Database → Create database** (production mode)
4. **Firestore → Rules** วางเนื้อหาจาก [firestore.rules](firestore.rules) แล้ว Publish
5. **Project settings → General → Your apps → Web app** คัดลอกค่า config
6. ในเครื่อง: คัดลอก `.env.example` เป็น `.env.local` แล้วเติมค่า
7. บน GitHub: **Settings → Secrets and variables → Actions** เพิ่ม secret 6 ตัวชื่อเดียวกับใน `.env.example`
   ([deploy.yml](.github/workflows/deploy.yml) อ่านไปใส่ตอน build ให้เอง)
8. **Authentication → Settings → Authorized domains** เพิ่ม `phawit-s.github.io`

แนะนำเพิ่ม: ที่ Google Cloud Console → Credentials → จำกัด API key ด้วย HTTP referrer
ให้ใช้ได้เฉพาะโดเมนของเรา

## ความปลอดภัย

โมเดลความปลอดภัยอยู่ที่ **Firestore Security Rules** ไม่ใช่ที่โค้ดฝั่งหน้าเว็บ
(API key ของ Firebase เป็นค่าสาธารณะตามการออกแบบ อยู่ในโค้ดได้ ไม่ใช่ความลับ)

สิ่งที่ทำไว้แล้ว:

- **แก้ผลได้เฉพาะเจ้าของทัวร์** — rules เช็ค `ownerUid` ทั้งของเดิมและของใหม่ โอนเจ้าของให้คนอื่นไม่ได้
- **อนุมัติตัวเองเป็นสตรีมเมอร์ไม่ได้** — `streamers/{uid}` เขียนได้เฉพาะผู้ดูแล ส่วนใบคำขอที่คนขอ
  เขียนเองบังคับให้ `status == 'pending'` เท่านั้น และ **เปิดช่องใหม่ต้องมีสิทธิ์สตรีมเมอร์ก่อน**
- **ส่งสลิปต้องล็อกอิน** (anonymous ก็ได้) และเปิดรับเฉพาะตอนผู้จัดเปิดระบบไว้ พร้อมจำกัดความยาวชื่อ/ข้อความ/ขนาดสลิป
- **สลิปถูกลบตอนอนุมัติ** เพราะใบที่อนุมัติแล้วต้องอ่านได้แบบสาธารณะ (widget ใน OBS ไม่ได้ล็อกอิน)
  รูปสลิปมีข้อมูลบัญชีของคนโอน จึงไม่ควรค้างอยู่ในที่ที่ใครก็อ่านได้
- **ข้อมูลติดต่อของทีมไม่ขึ้นคลาวด์และไม่ติดไปกับลิงก์แชร์** ([lib/safe.ts](lib/safe.ts) `stripContacts`)
- **กรอง URL ก่อนใส่ `href`/`src`** รับเฉพาะ http/https/mailto และ data URL ที่เป็นรูปจริง
  กัน `javascript:` ที่แฝงมากับข้อมูลจากลิงก์แชร์หรือคลาวด์
- **PIN โหมดผู้จัดไม่ถูกอัปขึ้นคลาวด์และไม่ติดไปกับลิงก์แชร์**

ข้อจำกัดที่ยังเหลือ (ยอมรับโดยตั้งใจ):

- PIN โหมดผู้จัดเป็นแค่กันมือลั่นฝั่ง client ไม่ใช่การยืนยันตัวตน — ตัวที่กันจริงคือ Google login + rules
- ทัวร์ที่เผยแพร่ขึ้นคลาวด์ตั้งเป็น public read ใครมีรหัสทัวร์ก็อ่านได้ (จำเป็นเพราะ OBS ไม่ล็อกอิน)
  อย่าใส่ข้อมูลที่ไม่อยากให้คนนอกเห็นลงในทัวร์ที่เผยแพร่
- ยังไม่ได้เปิด **App Check** — ถ้าเจอสแปมโดเนทหนักๆ ค่อยเปิดเพิ่มได้
- ไม่มีการตรวจสลิปกับธนาคาร ผู้จัดต้องดูเอง

## ข้อจำกัดที่ต้องรู้

เว็บนี้เป็น static ล้วน **ไม่มีเซิร์ฟเวอร์และไม่มีฐานข้อมูล** ทุกอย่างเก็บใน localStorage ของเครื่องที่เปิด
เพราะฉะนั้น:

- **การสมัครแข่ง** = ผู้จัดกรอกทีมเองในเครื่องผู้จัด คนอื่นสมัครจากเครื่องตัวเองแล้วส่งเข้ามาไม่ได้
- **โหมดผู้จัด (PIN)** กันมือลั่นเท่านั้น ไม่ใช่ระบบสิทธิ์จริง — เปิด devtools ก็เห็นทุกอย่าง
- **ระบบผู้ใช้** ใช้ "ชื่อ" เป็นตัวระบุตัวตน ไม่มีบัญชี ไม่มีรหัสผ่าน
- **แชร์** ทำโดยฝังข้อมูลทัวร์ทั้งก้อนไว้ใน URL (`#s=...`) คนเปิดจะเห็นสถานะ ณ ตอนที่กดแชร์
  ถ้าผู้จัดกรอกผลเพิ่มต้องส่งลิงก์ใหม่ (รูปปกไม่ติดไปกับลิงก์ เพราะจะยาวเกิน)

ถ้าอยากได้แบบสมัครข้ามเครื่อง / ผลอัปเดตสดทุกคน ต้องมี backend + ฐานข้อมูล

## โครงสร้าง

```text
app/            หน้าบ้าน: /  ·  /draw  ·  /wheel  ·  /tournament  ·  /c  ·  /song  ·  /account
  studio/       หลังบ้าน: layout เดียวครอบทุกหน้าลูก (แถบข้าง + ด่านสิทธิ์)
  widget/       กราฟิกสำหรับ OBS — พื้นหลังโปร่งใส ไม่มีเปลือกใดๆ
components/
  AppShell      แถบเมนูลอย + พื้นหลัง + ท้ายเล่ม ของหน้าบ้าน
  NavBar        แถบเมนูสาธารณะ (fixed) — เหลือแบรนด์ 2 เมนู ธีม/เสียง และบัญชี
  studio/       StudioShell (แถบข้าง+ด่าน), nav, StudioHome, RolesPanel,
                StreamerRequest (ฟอร์มขอสิทธิ์), StreamerGate, AdminOnly
  Randomizer    เครื่องมือสุ่มทีม → SetupScreen / DrawScreen / ResultScreen
  wheel/        Wheel (canvas), WheelView
  tournament/   TournamentsView, TournamentForm, TournamentDetail,
                TeamsPanel, BracketPanel, SchedulePanel, PrizePanel, PlayersView
  ui/           Panel, Button, ThemeSound
  fx/           BackgroundFX, GoldDust
hooks/          useTournament (reducer + persist), useClient, useRole (บทบาทของคนที่เปิดอยู่)
lib/            random, teams, game, brand, sound, theme, share, exportImage, wheel
  backend/      firebase, users, admin, roles (สิทธิ์สตรีมเมอร์ + คำขอ)
  tournament/   types, store, bracket, prize, players, admin, share
```

บทบาทของผู้ใช้ตอบจากที่เดียวคือ [hooks/useRole.ts](hooks/useRole.ts) — รวมสถานะจาก
`authStore` + `adminClaimStore` + `streamerStore` + รหัสเครื่อง แล้วคืนค่า `role` กับ `studio`
ทุกหน้าจอถามที่นี่ที่เดียว จะได้ไม่มีสองที่ตัดสินไม่ตรงกัน

หัวใจของสายแข่งอยู่ที่ [lib/tournament/bracket.ts](lib/tournament/bracket.ts) — `createBracket()` สุ่มคู่จาก seed
แล้ว `propagate()` ดันผู้ชนะเข้ารอบถัดไปให้เองทุกครั้งที่แก้ผล ทำให้แก้คะแนนย้อนหลังได้โดยสายไม่เพี้ยน

หัวใจอยู่ที่ [lib/teams.ts](lib/teams.ts) — `planTeams()` กางที่นั่งทั้งหมดออกเป็นลิสต์ล่วงหน้า
แล้ว `buildTeams()` ประกอบทีมจาก "จำนวนคนที่เปิดแล้ว" อย่างเดียว ทำให้ย้อนกลับ / ข้ามไปท้ายสุด
เป็นแค่การเปลี่ยนตัวเลขตัวเดียว ไม่มี state ซ้อนให้พัง
