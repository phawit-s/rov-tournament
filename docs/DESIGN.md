# คิวเพลง — ระบบดีไซน์

เว็บนี้ทำอย่างเดียว: ให้คนดูไลฟ์ขอเพลง YouTube และให้สตรีมเมอร์เปิดเพลงตามคิว
(ทัวร์นาเมนต์ สุ่มทีม วงล้อ นาฬิกา โดเนท ถูกตัดออกตุลาคม 2569 — ข้อมูลเก่าใน Firestore ยังอยู่)

คนใช้มีสามแบบ
- **คนดู** สแกน QR จากไลฟ์ด้วยมือถือ วางลิงก์ ส่ง จบในหนึ่งนาที
- **สตรีมเมอร์** เปิดตัวเล่นค้างไว้ทั้งคืน จัดคิว ตั้งค่า เอาลิงก์ widget ไปใส่ OBS
- **คนดูบนจอไลฟ์** เห็นแค่ widget เพลงที่กำลังเล่น

## หลักใหญ่

1. **สีมาจากเพลงเท่านั้น** หน้าจอเป็นขาว ดำ เทา สีเดียวที่มีคือปกเพลงกับสีที่ดูดออกมาจากปก
   (`lib/song/artwork.ts`) ปกเปลี่ยน สีของ "เวที" เปลี่ยนตาม ไม่มีสีแบรนด์ให้แย่งความสนใจ
   ยกเว้นสีสถานะเล็กๆ สามตัว: แดง = ไลฟ์อยู่, เขียว = เปิดรับเพลง, แดงเข้ม = ผิดพลาด
2. **ตัวหนังสือคุมลำดับชั้น** หัวข้อหนาสีดำล้วน ขนาดต่างกันชัด
   ไม่มีป้ายเล็กเหนือหัวข้อ ไม่มีตัวพิมพ์ใหญ่ทั้งคำ ไม่คั่นด้วย " · " ไม่ต่อท้ายลิงก์ด้วย "→"
3. **รายการเป็นแถว ไม่ใช่การ์ด** คิวเพลงคือเพลย์ลิสต์ คั่นด้วยเส้นบาง
   เลขลำดับใส่ได้เพราะคิวเป็นลำดับจริง ที่อื่นห้ามใส่เลขประดับ
4. **ปุ่มหลักหนึ่งปุ่มต่อหนึ่งงาน** สีดำทรงแคปซูล (โหมดมืดเป็นสีขาว) ปุ่มรองเป็นพื้นเทา
5. **ขยับเฉพาะตอนตอบการกระทำ** เพลงเข้าคิว เปลี่ยนเพลง เปิด/ปิดของ ไม่มีแอนิเมชันลอยเอง
   (ยกเว้นแถบเสียงเต้นบน widget ซึ่งบอกว่า "กำลังเล่นอยู่")

## สี

| ชื่อ (Tailwind) | สว่าง | มืด | ใช้กับ |
|---|---|---|---|
| `canvas` | `#FFFFFF` | `#000000` | พื้นหน้า |
| `fill` | `#F1F1F4` | `#1C1C1F` | ช่องกรอก ปุ่มรอง พื้นกลุ่ม |
| `fill-2` | `#E6E6EB` | `#2A2A2E` | hover ของ fill |
| `paper` | `#FFFFFF` | `#161618` | ของที่ลอย: เมนู dialog toast |
| `ink` | `#000000` | `#FFFFFF` | ตัวหนังสือหลัก ปุ่มหลัก |
| `onink` | `#FFFFFF` | `#000000` | ตัวหนังสือบนปุ่มหลัก |
| `muted` | `#5C5C66` | `#A3A3AD` | ตัวหนังสือรอง (คอนทราสต์ ≥ 6:1) |
| `faint` | `#8E8E98` | `#6E6E78` | placeholder ของที่ปิดอยู่ (ห้ามใช้กับเนื้อหาที่ต้องอ่าน) |
| `line` | `#E4E4E9` | `#2C2C31` | เส้นบาง ขอบช่องกรอก |
| `live` | `#D8232A` | `#FF453A` | ไลฟ์อยู่ |
| `open` | `#0F7A3B` | `#32D74B` | เปิดรับเพลง / ใช้ได้ |
| `danger` | `#C4271E` | `#FF6961` | ผิดพลาด |

**สีจากปก** ตั้งเป็นตัวแปร `--art` (`r g b`) บนกล่อง "เวที" แล้วใช้ `rgb(var(--art) / x)`
ปกยังไม่มา = เทากลาง ห้ามเอาสีจากปกไปทำตัวหนังสือบนพื้นขาว (คอนทราสต์ไม่แน่นอน)

## ตัวอักษร

ฟอนต์เดียวทั้งเว็บ: **Anuphan** (ไทยไม่มีหัว ทันสมัย อ่านง่ายบนจอ)
- น้ำหนักที่ใช้: 400 เนื้อหา · 500 ปุ่ม/ชื่อเพลงในแถว · 700 หัวข้อ — ไม่ใช้ต่ำกว่า 400
- สเกล (px): 13 · 15 · 17 · 20 · 24 · 32 · 44 · 60
  เนื้อหาหลัก 17 · ข้อความรอง 15 · ขั้นต่ำ 13 (ห้ามเล็กกว่านี้ ผู้ใช้เคยบ่นเรื่องอ่านยาก)
- line-height: เนื้อหา 1.6 · หัวข้อ 1.25 (ไทยมีวรรณยุกต์ซ้อน ต่ำกว่านี้หัวขาด)
- ตัวเลขลำดับ/เวลาใช้ `tabular-nums` (`.num`)
- ความยาวบรรทัดไม่เกิน ~70 ตัวอักษร (`max-w-prose` หรือ `max-w-[36rem]`)

## รัศมีมุม (ตามลำดับชั้น)

| ของ | รัศมี |
|---|---|
| เวที (กล่องเพลงที่กำลังเล่น) | 28px `rounded-stage` |
| แผ่น/กลุ่ม (sheet, dialog) | 20px `rounded-sheet` |
| ช่องกรอก | 14px `rounded-field` |
| ปก/รูปย่อ | 10px ใหญ่ · 6px เล็ก `rounded-art` / `rounded-thumb` |
| ปุ่ม ป้ายสถานะ | แคปซูล `rounded-full` |

ไม่มีเงาบนของที่วางอยู่บนพื้น ใช้เงาเฉพาะของที่ลอย (เมนู dialog toast)

## เลย์เอาต์

- ชิดซ้ายทั้งเว็บ ไม่จัดกลางยกเว้นหน้าว่าง/หน้าโหลด
- หน้าสาธารณะกว้างสุด 1120px ขอบ 20px (มือถือ) / 32px
- **หน้าขอเพลง** มือถือ: หัวช่อง → เวที → ฟอร์ม → คิว
  จอกว้าง: ซ้าย (เวที + ฟอร์ม, sticky) / ขวา (คิว)
- **สตูดิโอ** แถบข้าง 248px บนจอกว้าง แถบแท็บเลื่อนแนวนอนบนมือถือ เนื้อหากว้างสุด 960px
- ทุกหน้าต้องใช้ได้ที่ 360px ปุ่ม/แตะได้สูง ≥ 44px

## คำ

- เรียกของตามที่คนใช้เข้าใจ: "คิว" "ขอเพลง" "ตัวเล่น" "ลิงก์สำหรับ OBS"
- ปุ่มบอกสิ่งที่จะเกิด และใช้คำเดียวกันตลอดทาง: ปุ่ม "ส่งเข้าคิว" → toast "ส่งเข้าคิวแล้ว"
- error บอกว่าเกิดอะไรและแก้ยังไง ไม่ขอโทษ ไม่คลุมเครือ
- หน้าว่างบอกว่าต้องทำอะไรต่อ

## widget บนจอไลฟ์

ขนาด/พารามิเตอร์ต้องไม่เปลี่ยน (ลิงก์ใน OBS ของสตรีมเมอร์ใช้อยู่จริง)
`/widget/song/?ch=<id>` แถบยาว 620×300 · `&card=1` การ์ดสูง 380×530 · `&card=wide` การ์ดนอน 500×160
`&accent=` `&scale=` ยังรับ — widget ใช้ภาษาเดียวกับเว็บ: ปก + ตัวหนังสือหนา + สีจากปก
แอนิเมชันเป็น CSS transform/opacity ล้วน (ดูเหตุผลใน globals.css)
