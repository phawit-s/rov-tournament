# สะพานแชท TikTok → คิวขอเพลง

พิมพ์ `!เพลง แสงสุดท้าย` ในแชทไลฟ์ TikTok แล้วเพลงเด้งเข้าคิวของช่องเลย
โดยคนดูไม่ต้องเปิดลิงก์อะไรทั้งนั้น

โฟลเดอร์นี้เป็นของเสริม **ไม่รันก็ใช้ระบบขอเพลงผ่านหน้าเว็บได้ตามปกติ**

---

## ทำไมต้องรันบนเครื่องตัวเอง

TikTok ไม่มี API สาธารณะให้อ่านคอมเมนต์ในไลฟ์ — ที่มีในเอกสารนักพัฒนาคือ
เรื่องโพสต์กับโปรไฟล์ ไม่มีแชท ทางเดียวที่อ่านได้จริงคือต่อ WebSocket ภายใน
ของ TikTok ซึ่งต้องมีลายเซ็นจากบริการภายนอก และต้องเปิดค้างตลอดเวลาที่ไลฟ์อยู่

สองข้อนี้ทำในเว็บ static ไม่ได้ (เบราว์เซอร์โดน CORS บล็อกและเซ็นไม่ได้)
และทำใน Cloudflare Worker ธรรมดาก็ไม่ได้ เพราะ Worker ตายทันทีที่ตอบคำขอเสร็จ
มันไม่ใช่โปรแกรมที่เปิดค้างได้

เครื่องที่เปิดอยู่แล้วตอนไลฟ์ก็คือเครื่องของคนไลฟ์ — เลยเอามาไว้ตรงนี้

```
แชท TikTok ──▶ สะพาน (เครื่องเรา) ──▶ Worker ──▶ Firestore ──▶ คิว + widget เด้งเอง
                  ฟังอย่างเดียว        ตรวจ+เขียน
```

สะพานทำแค่ฟังแชทกับส่งต่อ **การตัดสินใจทั้งหมดอยู่ที่ Worker**
(ช่องเปิดรับอยู่ไหม คิวเต็มยัง คนนี้ขอเกินโควตาหรือยัง) เพราะสคริปต์ที่รัน
บนเครื่องผู้ใช้แก้ได้ ใครก็เขียนตัวเลียนแบบยิงเข้ามาได้

---

## ต้องมีอะไรก่อน

1. **Node.js 18 ขึ้นไป** — `node -v` เช็คได้
2. **Worker deploy แล้ว** พร้อมบัญชีบอท (`BOT_EMAIL` / `BOT_PASSWORD` /
   `FIREBASE_API_KEY` / `FIREBASE_PROJECT`) — ตัวเดียวกับที่ใช้อนุมัติสลิป
   ดู [../worker/README.md](../worker/README.md)
3. **uid ของบอทอยู่ในหน้า ช่อง → ผู้ดูแลระบบ** แล้ว
4. **publish `firestore.rules` ตัวล่าสุด** ที่ Firebase Console
   (ตัวเก่าไม่ยอมให้บอทเขียนใบแทนคนดู)
5. **คีย์ YouTube ใน Worker** ถ้าอยากให้คนดูพิมพ์ *ชื่อเพลง* ได้
   ไม่มีคีย์ก็ยังใช้ได้ แต่ต้องวางลิงก์ YouTube มาเท่านั้น

## ตั้งค่า

```bash
cd bridge
npm install
cp .env.example .env
```

สุ่ม token ขึ้นมาหนึ่งอัน

```bash
node -e "console.log(crypto.randomUUID().replace(/-/g,''))"
```

เอาค่าที่ได้ใส่ **ทั้งสองที่ให้ตรงกัน**

```bash
# ฝั่ง Worker (รันในโฟลเดอร์ worker/)
wrangler secret put INGEST_TOKEN
wrangler deploy
```

```ini
# ฝั่งสะพาน — ไฟล์ bridge/.env
TIKTOK_USER=ชื่อ_tiktok_ที่ไลฟ์
WORKER_URL=https://slip-verify.xxxx.workers.dev
INGEST_TOKEN=ค่าที่สุ่มมา
CHANNEL=handle_ของช่อง
```

`CHANNEL` ใส่ handle ได้เลย — คือตัวที่อยู่ท้ายลิงก์หน้าขอเพลง
(`.../song/#h=affarain` → ใส่ `affarain`) หรือจะใส่ไอดีเอกสารของช่องก็ได้

## ทดสอบก่อนไลฟ์จริง

```bash
node tiktok-song-bridge.mjs --test "แสงสุดท้าย bodyslam"
```

ตัวนี้ยิงคำขอหนึ่งอันไปที่ Worker ตรงๆ **โดยไม่ต่อ TikTok**
มีไว้แยกให้ออกว่าปัญหาอยู่ฝั่งไหน — เปิดไลฟ์แล้วไม่มีอะไรเกิดขึ้น
กับ Worker ตั้งค่าไม่ครบ หน้าตาเหมือนกันเป๊ะเวลาไม่มีตัวทดสอบ

ผ่านแล้วจะขึ้น

```
[20:31:04] ✓ คิวที่ 1 · แสงสุดท้าย - BODYSLAM · ขอโดย @test_user
```

แล้วเปิดหน้าจัดการช่องดูได้เลย ใบจะอยู่ในคิวพร้อมป้าย **TikTok**
(ลบทิ้งได้ตามปกติ)

## ใช้งานจริง

```bash
npm start
```

เปิดทิ้งไว้ตอนไลฟ์ ปิดด้วย `Ctrl+C`
เปิดก่อนกดไลฟ์ก็ได้ — มันจะรอแล้วต่อให้เองเมื่อไลฟ์เริ่ม และต่อใหม่ให้เอง
ถ้าเน็ตสะดุดกลางคัน

คนดูพิมพ์ได้สองแบบ

| แบบ | ตัวอย่าง | กินโควตา YouTube |
| --- | --- | --- |
| ชื่อเพลง | `!เพลง คิดถึง etc` | ✅ ครั้งละ 1 (จาก ~100/วัน) |
| ลิงก์ | `!เพลง https://youtu.be/xxxxxxxxxxx` | ❌ ไม่กิน |

จะมีบรรทัดขึ้นในหน้าต่างสะพานทุกครั้งที่มีคนขอ ทั้งที่ผ่านและไม่ผ่าน

## เรื่องโควตา YouTube (ข้อจำกัดที่สำคัญที่สุด)

โควตาฟรีของ YouTube Data API คือ 10,000 หน่วย/วัน และการค้นหาครั้งละ 100 หน่วย
= **ค้นได้ราววันละ 100 ครั้ง** ซึ่งไลฟ์ที่คนดูคึกๆ หมดได้ใน 20 นาที

ตัวช่วยที่ใส่ไว้แล้ว

- **แคชผลค้นหา** ฝั่ง Worker — คนขอเพลงฮิตซ้ำๆ กันจะไม่กินโควตาซ้ำ
  (ผูก KV ชื่อ `SONG_CACHE` เพิ่มจะข้ามการรีสตาร์ทได้ด้วย ดู `worker/wrangler.toml`)
- **หน่วงรายคน** `COOLDOWN_SEC` — ค่าเริ่มต้น 45 วินาที
- **เพดานต่อช่อง/ต่อคนต่อนาที** ฝั่ง Worker

ถ้ายังไม่พอ ทางที่ได้ผลที่สุดคือประกาศในไลฟ์ให้วาง **ลิงก์** แทนชื่อเพลง
เพราะลิงก์ใช้ oEmbed ซึ่งไม่มีโควตาเลย

## แก้ปัญหาที่เจอบ่อย

| ที่ขึ้นในหน้าต่างสะพาน | ต้องแก้ตรงไหน |
| --- | --- |
| `ยังไม่ได้ติดตั้งไลบรารี` | `npm install` ในโฟลเดอร์นี้ |
| `INGEST_TOKEN ... ไม่ตรง` | ค่าใน `.env` กับ `wrangler secret put INGEST_TOKEN` ไม่ตรงกัน หรือลืม `wrangler deploy` |
| `Worker ยังไม่ได้ตั้ง INGEST_TOKEN` | ยังไม่ได้ใส่ secret ฝั่ง Worker |
| `หาช่องไม่เจอ` | `CHANNEL` ผิด — ลองใส่ไอดีเอกสารแทน handle |
| `ช่องนี้ปิดรับคำขอเพลงอยู่` | เปิดสวิตช์ "เปิดรับคำขอเพลง" ที่หน้าจัดการช่อง |
| `เขียนคิวไม่ผ่าน (write-failed-403)` | uid บอทยังไม่อยู่ใน `admins` หรือยังไม่ได้ publish `firestore.rules` ตัวใหม่ |
| `ยังไม่ได้เริ่มไลฟ์` วนซ้ำ | ปกติ — รอจนกดไลฟ์ (ถ้าไลฟ์แล้วยังขึ้น เช็คว่า `TIKTOK_USER` สะกดถูก) |
| ต่อไม่ติดบ่อย / โดนปฏิเสธ | ใส่ `SIGN_API_KEY` จาก eulerstream.com |

## ข้อควรรู้

**ไลบรารีนี้ไม่ใช่ของทางการ** `tiktok-live-connector` เป็นการถอดรหัสโปรโตคอล
ภายในของ TikTok เอง เวลา TikTok เปลี่ยนของ มันจะพังจนกว่าไลบรารีจะอัปเดตตาม
(`npm update` แล้วลองใหม่) การอ่านแชทเฉยๆ ไม่ใช่สิ่งที่ TikTok ไล่แบน
แต่ก็ไม่มีอะไรรับประกัน — อย่าเอาไปผูกกับอะไรที่ขาดไม่ได้

**สะพานตอบกลับในแชท TikTok ไม่ได้** เพราะการพิมพ์ต้องใช้บัญชีที่ล็อกอินอยู่
ซึ่งเป็นคนละเรื่องกับการอ่าน คนดูจะรู้ว่าเพลงเข้าคิวแล้วจาก widget บนจอไลฟ์
หรือจากที่สตรีมเมอร์พูดเอง

**ทางเลือกที่ไม่ต้องรันสะพาน** ถ้าใช้ TikFinity หรือ Social Stream Ninja อยู่แล้ว
ตั้งให้มันยิง webhook มาที่ `POST <WORKER_URL>/?ingest=1` ได้เลย
ใส่ header `Authorization: Bearer <INGEST_TOKEN>` แล้วส่ง JSON

```json
{ "channelId": "handle", "user": { "id": "someone", "name": "Someone" }, "text": "!เพลง ชื่อเพลง" }
```

ใช้ `text` (บรรทัดแชทดิบ) แทน `query` ได้ — Worker จะตัดคำสั่งให้เอง
และเมินบรรทัดที่ไม่ใช่คำขอเพลง
